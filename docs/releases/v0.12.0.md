## Highlights

- **Extend Spot without maintaining a fork.** Embedding applications can install methods on the existing `spot` object and augment its TypeScript interfaces. Extensions share the SDK's request transport, errors, retries and cancellation. [#46](https://github.com/melonamin/spot/pull/46)
- **Use the standard image with your own SDK.** Mount trusted JavaScript and type declarations, and Spot serves them after core at `/spot.js` and `/spot.d.ts`. Sites continue to load one script. [#46](https://github.com/melonamin/spot/pull/46)
- **Keep integration context and settings together.** Delegated sessions retain opaque private identity context. Namespaced site settings survive publishing, cloning and sharing edits, and a trusted integration can read its namespace under the viewer's site access. [#46](https://github.com/melonamin/spot/pull/46)

## For integrators

- Install extensions synchronously with `spot.use({ apiVersion: 1, install(sdk, { request }) { /* ... */ } })`. Type declarations can augment `SpotSDK.Spot` and `SpotSDK.AI`.
- Set `SPOT_SDK_EXTENSIONS_DIR` or `--sdk-extensions-dir` to a read-only directory. Spot appends regular `*.js` and `*.d.ts` files in filename order at startup. Restart after changing the files. The combined extension contents are limited to 8 MiB; matching symlinks, nonregular files and unreadable paths fail startup.
- Extension code is trusted operator code and runs with each site's browser authority. Site uploads cannot install extensions. Embedding applications still route and authorize their own backend APIs.
- Signed delegated-login tokens can carry a namespaced `context` object. It is retained in the host-bound HttpOnly session and omitted from public identity JSON. Signed cookies are not encrypted; do not include secrets.
- `_access.json` accepts an `extensions` object containing namespaced objects. `GET /api/sites/{name}/extensions/{namespace}` requires trusted forward-auth and current viewer access to the site; visitor cookies alone do not admit the call.

## Upgrade notes

- No database migration or site-file migration is required.
- Leaving the extension-directory option unset preserves the standalone SDK behavior.
- The server image and development toolchain use Go 1.26.11 to address [GO-2026-6859](https://pkg.go.dev/vuln/GO-2026-6859).
